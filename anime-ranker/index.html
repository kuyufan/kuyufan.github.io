對戰記錄（最近 60 場）

這個排名如何運作？

計分：每部動畫起始 Elo 1500 分。每場對戰依兩部的預估勝率調整分數。若 A 的預期分數為 E=1/(1+10^((R_B-R_A)/400))，則新分數為 R_A'=R_A+K×(S-E)，其中勝／和／敗的 S 分別為 1、0.5、0。兩部動畫分數增減總和為 0。

K 值：K=32 是預設。數值越大，單場影響越大。系統會逐場記錄當時的 K 值，之後修改 K 不會改動先前對戰的計分方式。

智慧配對：優先考慮對戰較少、評分相近，而且最近沒有碰過面的兩部作品；仍會偶爾安排跨分數對戰。若要確保新加入的動畫被看見，可切換「優先未評作品」。

封存與刪除：封存只停止參與新對戰，歷史紀錄仍保留並影響其他作品分數。永久刪除則連它參與的對戰一起刪除，整個 Elo 排名重新計算。

資料位置：未登入時使用瀏覽器 localStorage；設定 Firebase 並登入後，資料儲存在 Cloud Firestore，手機和電腦使用同一帳號可自動同步。同步期間需保持連線；如遇失敗請立即備份 JSON。

資料安全與注意事項

帳號隔離：Firestore 安全規則僅允許已登入使用者讀寫自己 UID 下的資料。Firebase Web 設定屬於公開識別資訊，不能代替資料庫安全規則。

跨裝置：兩台裝置都要連上網路並登入同一個 Firebase 帳號。修改後會自動更新另一台的畫面；若網路不穩、授權失敗或超出額度，會出現警告。

舊資料遷移：第一次登入尚未初始化的帳號時，可將目前瀏覽器的資料上傳。建議在遷移前先下載 JSON 備份。

不能只靠雲端：Firebase 不是永久無限免費儲存，須留意專案額度及帳號維護。重要紀錄仍建議定期下載備份。
